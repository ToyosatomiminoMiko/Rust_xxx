# GB/T 9704-2012 公文格式 · 字体要求、授权分析与开源落地方案

> 本文是 `gbt9704` 生成器的**字体侧落地文档**：把「标准要求的字体」翻译成「可实际取得、可校验、可嵌入 PDF 的字体文件与槽位约定」。
> 配套产物：`gbt9704/fonts-manifest.json`（机器可读清单）、`gbt9704/scripts/fetch-fonts.sh`（幂等下载/校验脚本）、`gbt9704/fonts/`（实际下载的字体，已被 `.gitignore` 忽略）。
> 生成日期：2026-11-07。实测环境：fontconfig 2.18.3（fc-scan）、Python 3.15、fontTools 4.68.0。

## 0. 结论速览（先看这段）

1. **标准提到的「小标宋、仿宋」不是指定唯一字库。** 标准原文用的是「**一般用** 2 号小标宋体字」「**推荐使用**小标宋体字」「如无特殊说明……**一般用** 3 号仿宋体字，**特定情况可以作适当调整**」；GB/T 9704-2012 没有写「必须使用方正小标宋简体」之类的字样。但实务中文档外观的事实标准就是方正小标宋 + 仿宋_GB2312，严格送审时建议自备商业字体。
2. **官方字体（方正小标宋简体、仿宋_GB2312、楷体_GB2312、黑体、宋体）是商业/系统字体，不能随本仓库再分发。** 因此项目策略是：不提交字体二进制；提供下载脚本 + 校验值 + 开源替代；用户本机有商业字体时由生成器优先探测使用。
3. **已实际下载并逐项实测 10 个开源字体文件，共约 121 MB**（`fonts/`），全部通过 SHA256 校验，脚本可重复执行（第二次运行全部「已就绪/缓存命中」）。字体家族名、PostScript 名、字符覆盖、字宽、`fsType` 均由 `fc-scan` + fontTools 实测，不是照抄网页。
4. **「小标宋」没有可自由使用的等价开源字体**（结论经检索与实测确认，开源社区目前没有「小标宋」字族）。最接近的是 **Noto Serif CJK SC Bold**（宋体加粗骨架，OFL），次选 **FandolSong-Bold**（GPL）。风险：笔画粗细、字面率、字形细节与方正小标宋仍有可见差异；严格合规请用户自备方正小标宋简体。
5. **仿宋槽位结论**：`FandolFang` 的现代仿宋骨架**观感更接近仿宋_GB2312**；`朱雀仿宋` 是 OFL 可分发字体，但以 1932 年「南宋」活字为蓝本、风格化明显，且当前是 **v0.212 技术预览**（GBK 覆盖 52.66%、缺全角数字、GB18030 扩展区仅 12/32 样本）。因此推荐 **FandolFang 作本地默认**（GPL，仅本地用）、**朱雀作 OFL 备选**、**Noto Serif CJK SC 作缺字回退**；若需要「可随软件分发的合规默认字体」，把首选换成朱雀并接受其预览版差异。
6. **字符覆盖的硬事实**：GB2312（6763 汉字）——本次所有字体均 100% 覆盖；GBK（20902 汉字）——Noto / 霞鹜文楷 100%，朱雀 52.66%，Fandol 38%；**GB18030 扩展区（含 4 字节区）没有一款开源字体覆盖完整**（最好的是霞鹜文楷 22/32 样本，`𠀀` 等无一覆盖）。公文出现生僻字（人名、地名）时必须回退到用户自备的全覆盖字体或系统字体，**不能静默丢字**。
7. **机器可读槽位约定已固定**：`title / small_biaosong / body_fangsong / heiti / kaiti / song / page_number / issuer_mark / record`，Rust 生成器直接读 `gbt9704/fonts-manifest.json` 的 `slots` 字段即可。

## 2. 字号、版心与 22 行 × 28 字网格（阶段 2 排版必须看懂）

- 用纸：A4，210 mm × 297 mm（5.1）。
- 页边：天头（上白边）37 mm ± 1 mm，订口（左白边）28 mm ± 1 mm；**版心 156 mm × 225 mm**（5.2.1）。
- 行数/字数：**一般每面 22 行，每行 28 个字，并撑满版心**（5.2.3；「特定情况可以作适当调整」）。
- 颜色：文字默认黑色（5.2.4）。

**网格换算**（156 mm = 442.2047 pt，225 mm = 637.7953 pt）：

| 项目 | 计算 | 结果 |
|---|---|---|
| 每字横向步进 | 442.2047 / 28 | **15.7929 pt** |
| 行距（竖向步进） | 637.7953 / 22 | **28.9907 pt** |
| 术语「一行」定义 | 一个汉字高度 + 3 号汉字高度的 7/8 = 16 + 14 | **30 pt** |

**两个必须注意的坑：**

1. **3 号字 16 pt 比网格步进宽。** 全角汉字字宽 = 16 pt（本项目字体全部 1000/1000 em），28 字 = 448 pt = **158.03 mm**，比版心 156 mm 多 **2.03 mm**（每字 0.207 pt）。所以「28 字正好撑满 156 mm」与「字号必须 16 pt」在几何上不能同时严格成立。实现三选一：
   - **(A) Word 文档网格行为**：每字按 15.7929 pt 步进排版（字面轻微重叠/紧缩），最接近真实 Word 公文模板；
   - **(B) 横向缩放 98.7%**（每字 15.79 pt 墨迹宽），视觉均匀但改变了字形比例；
   - **(C) 放宽版心到 158 mm**：不推荐（偏离 156 mm 标准）。
   本项目建议默认 **(A)**，并在文档里提供开关；阶段 2 用对照 PDF 实测取舍。
2. **术语里的「一行 = 30 pt」不是 22 行网格的行距。** 30 pt 用于「空一行/空二行」等垂直间距（如标题在红色分隔线下空二行、发文字号在标志下空二行）；22 行网格的行距是 **28.9907 pt**。两者不可混用，否则一页排不下 22 行。

**字号 → 常用换算**：2 号 22 pt（标题）；3 号 16 pt（正文/密级/一级标题/签发人/附件标注/附注）；4 号 14 pt（抄送/印发/页码）。

## 3. 官方/商业字体清单与授权分析

### 3.1 标准「事实上的指定字体」

> 说明：`FZXiaoBiaoSong-B05S` 的字体名/PostScript 名可由字体文件及[字体家条目](https://www.zitijia.com/i/283147194796624953.html)佐证；商业字体的授权范围以[方正字库商业授权](https://www.foundertype.com/index.php/about/powerbus.html)及用户实际购买的授权书为准。中易系 Windows 字体请遵循微软/中易的最终用户许可，**不要**把 `simfang.ttf`/`simkai.ttf`/`simhei.ttf`/`simsun.ttc` 提交进仓库。

### 3.2 授权结论（本项目的处理方式）

1. **字体二进制不进版本库**：`gbt9704/fonts/` 已在 `.gitignore` 中；仓库只保留 `docs/fonts.md`、`fonts-manifest.json`、`scripts/fetch-fonts.sh`。
2. **生成器运行时按「用户自备 → 开源首选 → 开源回退 → 系统字体」的顺序解析字体**（见 §5、§7）；用户本机装了商业字体就优先用，符合标准观感；没装则用开源替代并在输出里给出警告。
3. **用户自备商业字体时，嵌入/分发许可由用户自行负责**（重点看字体的 `fsType` 嵌入位；见 §8.1）。生成器只读文件、不复制、不再分发。
4. 开源替代的许可分两类：**OFL 1.1**（Noto / 霞鹜文楷 / 朱雀；可嵌入、可随软件分发）与 **GPL + 字体嵌入例外**（Fandol；嵌入 PDF 可以，但**随项目分发字体文件**需履行 GPL，Debian 曾因此拒绝打包）。所以 Fandol 只作为「本地下载回退」，不作为随软件分发的默认字体。

### 3.3 「标准只是推荐，不是唯一合法字体」的条款依据

这是本项目选择开源替代的合规基础，原文依据如下：

- **5.2.2**：「如无特殊说明，公文格式各要素**一般用** 3 号仿宋体字。**特定情况可以作适当调整**。」
- **7.3.1**：「**一般用** 2 号小标宋体字，编排于红色分隔线下空二行位置……」
- **7.2.4**：「……**推荐使用**小标宋体字，颜色为红色，以醒目、美观、庄重为原则。」
- **10.1 / 10.2 / 10.3**：「……**推荐使用**红色小标宋体字。」
- **7.3.7**：只规定「『附件』二字及附件顺序号用 3 号黑体字」，未指定黑体品牌。

结论：

- 标准对**字号、颜色、位置、排布**是硬要求；对**具体字库品牌**只给出「一般用/推荐」的字体**类别**（小标宋、仿宋、黑体、楷体、宋体），没有规定必须使用某一厂商的某款字体。
- 「仿宋体字」「小标宋体字」是**字形类别**要求；只要字形属于该类别且观感符合「醒目、美观、庄重」，在标准文本层面并不违规。
- 但**发文机关/审核环节的实务惯例**通常按方正小标宋 + 仿宋_GB2312 的外观验收，且商业字体厂商对「公文用字」有明确授权要求。因此：
  - **本工具默认提供开源替代**（可离线生成、可回归测试、无授权风险）；
  - **严格送审场景请配置用户自备的方正小标宋简体 / 仿宋_GB2312 / 楷体_GB2312**，并由用户确保授权；
  - 合规责任最终在发文机关，本文档不构成法律意见。

  "color": "black", "color_hex": "#000000",

  "fallback_open_fonts": ["FandolSong-Bold.otf"],
  "user_supplied_fonts": ["方正小标宋简体", "FZXiaoBiaoSong-B05S", "方正小标宋_GBK"],

## 6. 关键差距深入分析

### 6.1 小标宋：**没有可自由使用的等价开源字体**

「小标宋」是**宋体类的标题/标志用字**：比正文宋体粗、比粗宋更收、横细竖粗、字形方正、字面率大、起收笔棱角分明；公文标题和红色机关标志都用它。开源社区目前**没有**名为「小标宋」的字族，也没有 OFL 授权的等价复刻（检索 CTAN、Google Fonts、GitHub 上的开源中文字体项目均未发现；Fandol/思源/霞鹜/朱雀都没有对应字重风格）。

**可用近似方案（按接近程度排序）**：

| 方案 | 许可 | 与方正小标宋的差距 | 风险 |
|---|---|---|---|
| **Noto Serif CJK SC Bold**（本项目首选，25.5 MB） | OFL 1.1 | 宋体骨架相同；但 Bold 字重偏重、横竖对比与字面率不同，笔画更「现代」 | 标题观感偏粗；机关标志放大后差异更明显 |
| **FandolSong-Bold**（回退，GPL） | GPL + 字体例外 | 传统宋体加粗，比 Noto Bold 略「瘦」、细节更朴素 | GPL 不宜随项目分发；质量一般 |
| **思源宋体 SemiBold/Medium**（未下载，可选） | OFL 1.1 | 字重比 Bold 轻，可能与「小标宋」的「粗但不肥」更接近 | 需从 Adobe release（~100 MB 级）另取；本项目未纳入以控体积 |
| **用户自备方正小标宋简体** | 商业 | **0（事实标准）** | 需采购/确保嵌入授权；不能随项目分发 |

**结论/建议**：默认用 `NotoSerifCJKsc-Bold.otf` 输出可交付的开源版；在 manifest/配置中保留 `user_supplied_fonts` 最高优先级，装了方正小标宋就自动切换。**不要宣称开源字体「等同」小标宋**——差异是客观存在的，严格送审请自备商业字体。

### 6.2 仿宋：FandolFang vs 朱雀仿宋，到底哪个更接近「仿宋_GB2312」？

先明确事实：**仿宋_GB2312 是商业/系统字体（中易），不是开源字体，且只覆盖 GB2312 的 6763 个汉字**。以下判断基于字形谱系与实测覆盖（没有商业原字做像素级对比，故是「观感/谱系」结论而非像素结论）：

| 维度 | FandolFang | 朱雀仿宋 v0.212 |
|---|---|---|
| 谱系/风格 | 现代仿宋骨架（与华丰真宋一系的现代仿宋观感接近），横竖粗细较均匀、字面规整 | 1932 年「南宋」活字再刻：重心略靠右下、中宫收紧、撇捺舒展、笔画粗细对比强，风格化/书卷气明显 |
| 与仿宋_GB2312 的接近度 | **更接近**（同为现代正文仿宋观感） | 差异较大（偏民国活字），不是同一视觉谱系 |
| GB2312 覆盖 | 6763/6763（100%） | 6763/6763（100%） |
| GBK 覆盖 | 7,942/20,902（38.0%） | 11,006/20,902（52.66%） |
| GB18030 样本 | 4/32 | 12/32 |
| 全角数字 ０–９ | 10/10 | **0/10（缺失）** |
| 轮廓格式 | CFF/OTF（CID-keyed） | TrueType glyf（TTF，PDF 嵌入更省心） |
| 许可 | GPL-3.0-or-later + 字体例外（**不宜随项目分发**） | **OFL 1.1（可随软件分发/嵌入）** |
| 稳定性 | 2015 年后未更新（稳定但老） | **v0.212 技术预览**，字形/字符集仍会变 |
| 可变字体 | 否 | 否 |

**结论**：

- **「最接近仿宋_GB2312」的是 FandolFang**（谱系 + 观感）；本项目 `body_fangsong` 默认选它。代价是 GPL，仅适合「本地下载、本地生成」，不适合随软件分发字体文件。
- **朱雀仿宋是唯一 OFL 许可、可随软件分发的仿宋**，但：① 技术预览、② 风格化明显、③ 缺全角数字、④ GBK/GB18030 覆盖不足——**不建议作为公文正文的唯一字体**。它更适合作为「OFL 合规场景的备选 + 缺字第二回退」。
- **正文的最终兜底是 Noto Serif CJK SC**：GBK 100% 覆盖；它虽然是宋体不是仿宋，但在「宁可字体风格略变、也不丢字」的前提下是正确取舍。阶段 2 需要记录「用了回退字体」的警告，便于人工复核。
- 字宽方面：**三款字体全角汉字都是 1000/em、16 pt 时每字 16 pt**，同一段 3 号字 28 字的**行宽完全相同**，差异只在墨迹/字面率，不在步进。

### 6.3 楷体、黑体、宋体

- **楷体**：首选 `LXGWWenKai`（OFL，GBK 100%，语义上是「楷体」），但它是基于日文 Klee One 扩改的，少量字形保留日式写法（如部分「骨/角/直/每」类结构）。若追求中易楷体_GB2312 的严格字形，用 `FandolKai`（GPL）或用户自备 `楷体_GB2312`。楷体只用于签发人姓名与二级标题，文字量小，观感差异影响有限。
- **黑体**：`Noto Sans CJK SC`（OFL，GBK 100%）是最稳的黑体替代；`FandolHei` 作 GPL 回退。注意标准要求的是**黑体**（无衬线），不要用「加粗宋体」冒充。
- **宋体**：`Noto Serif CJK SC`（OFL，GBK 100%）用于页码与缺字回退；`FandolSong` 作 GPL 回退。页码只用半角数字，所有字体都 10/10 覆盖。

### 6.4 字符覆盖：GB2312 只是起点

| 字集 | 汉字数 | 本次字体覆盖情况 |
|---|---|---|
| GB2312 | 6,763 | **全部 100%**（Fandol / Noto / 霞鹜 / 朱雀） |
| GBK | 20,902（含扩展 A 部分） | Noto 100%、霞鹜文楷 100%、朱雀 52.66%、Fandol 38.0% |
| GB18030（4 字节扩展区） | 全 Unicode 映射（2022 版另有强制实现级别） | **没有一款完整**；样本最好 22/32（霞鹜），Noto 20–21/32，朱雀 12/32，Fandol 4/32 |

实测的「生僻字对号」示例（`Y` = 有字形，`.` = 缺）：

| 字符 | Fandol 系 | Noto 系 | 霞鹜文楷 | 朱雀 |
|---|---|---|---|---|
| 龘 / 赟 / 堃 / 喆 / 玥 / 珺 / 旻 / 犇 / 骉 | . | Y | Y | Y |
| 頔 / 猋 / 麤 | . | Y | Y | . |
| 𠮷（U+20BB7）、𰻝（U+30EDD）、𰻞（U+30EDE） | . | Y | Y | . |
| 𠀀（U+20000） | . | . | . | . |
| 甯 / 淼 | Y | Y | Y | Y |

**结论与策略**：

- GB2312 字体（仿宋_GB2312/楷体_GB2312）本身就只覆盖 6763 字，**公文出现 GB18030 生僻字时，任何一套「标准字体」都可能缺字**——这不是开源替代独有的问题。
- 生成器必须实现**逐字回退 + 缺字报告**：
  1. 首选字体（或用户商业字体）→ 2. `fallback_open_fonts` 顺序 → 3. 系统 fontconfig（`fc-match :charset=U+XXXX`）→ 4. 仍缺字则**报错并列出码位**（不能输出豆腐块或空白）。
- 对「必须用 GB18030 全覆盖」的机关，建议配置用户自备的方正 GB18030 版字体（如方正小标宋_GBK/方正仿宋_GBK 等）或系统级全覆盖字体；本项目的开源字体只能作为「常用字 + 部分生僻字」的基线。
- 参考：GB/T 9704-2012 第 9 章要求数字/标点符合 GB/T 15835 等规范；字体侧至少要保证全角标点（，。、；：！？（）《》〔〕“”—…· 等）齐全——实测所有入选字体 31/31 覆盖。

### 6.5 字宽、字面率与可变字体

- 所有入选字体 `unitsPerEm = 1000`，全角汉字 advance 唯一值 = 1000 → 任何字号下每字宽度 = 字号值（16 pt 字 = 16 pt 宽）。
- 因此**同一字号、同一段文字在不同候选字体下行宽完全一致**；差异体现在字形墨迹宽度（字面率）、笔画粗细、中宫松紧，而不是排版步进。阶段 2 做「28 字 × 22 行」对照时，应重点看**字形是否溢出网格**、**相邻字是否粘连**，而不是行宽。
- 全部为静态字体（非可变）；如果需要中间字重（如小标宋近似用 SemiBold），需要另取静态实例（见 §6.1）。

## 7. 用户自备商业字体的回退与探测

### 7.1 解析优先级

```
用户显式配置的字体文件（config.font_path，最高）
  → 用户自备商业字体（按 manifest 的 user_supplied_fonts 家族名探测，如已安装）
    → preferred_open_font（本仓库 fonts/）
      → fallback_open_fonts（逐字回退）
        → 系统字体（fc-match --sort :charset=…）
          → 报错 + 列出缺失码位（禁止静默丢字）
```

> 商用环境推荐把「用户自备商业字体」放在开源首选之前，以满足送审观感；开源字体作为无商业字体环境/CI 的默认。

### 7.2 探测用的家族名 / PostScript 名

| 商业字体 | 家族名候选（fontconfig 可能值） | PostScript 名 | 用于槽位 |
|---|---|---|---|
| 方正小标宋简体 | `方正小标宋简体`、`FZXiaoBiaoSong-B05S`、`方正小标宋_GBK` | `FZXiaoBiaoSong-B05S` | title / small_biaosong / issuer_mark |
| 仿宋_GB2312 | `仿宋_GB2312`、`FangSong_GB2312`、`仿宋`、`FangSong` | `FangSong_GB2312` | body_fangsong / record |
| 楷体_GB2312 | `楷体_GB2312`、`KaiTi_GB2312`、`楷体`、`KaiTi` | `KaiTi_GB2312` | kaiti |
| 黑体 | `黑体`、`SimHei`、`中易黑体` | `SimHei` | heiti |
| 宋体 | `宋体`、`SimSun`、`中易宋体` | `SimSun` | song / page_number |

探测建议：优先用 `fontconfig`（`fc-match -f '%{file}\n' 'FangSong_GB2312'`）或遍历字体目录读 name 表；**不要**把 `%WINDIR%\Fonts\*` 的路径写死。检测到商业字体后，还要检查其 `fsType` 嵌入位（§8.1）：若字体禁止嵌入（`fsType & 0x2`），生成 PDF 时必须报错/降级，不能强行嵌入。

## 8. 阶段 2 PDF 嵌入注意事项

### 8.1 `fsType`（OS/2 表）——能不能嵌入、能不能子集化

| 位值 | 含义 | 本项目实测 |
|---|---|---|
| `0x0` | Installable Embedding（无限制） | Noto（Sans/Serif）、霞鹜文楷 |
| `0x2` | Restricted License（禁止嵌入） | 无（遇到要拒绝嵌入） |
| `0x4` | Preview & Print（只读预览/打印） | 无 |
| `0x8` | Editable Embedding（允许可编辑嵌入） | Fandol 全部、朱雀 |
| `0x100` | No Subsetting（禁止子集化） | 无 |
| `0x200` | Bitmap Embedding Only | 无 |

实测结论：**10 个字体全部可嵌入**（无 `0x2`、无 `0x100`）。Noto/霞鹜为 `0x0`，Fandol/朱雀为 `0x8`，都可子集化。用户自备商业字体需要在加载时检查，`fsType & 0x2` 必须报错。

### 8.2 CFF/OTF vs TrueType/TTF

- **Noto CJK、Fandol 是 CFF（CID-keyed OpenType，.otf）**：PDF 里对应 `Type0` + `CIDFontType0`（CFF CIDFont），字体文件含 CID→GID 映射；子集化需要保留 CID 结构。
- **霞鹜文楷、朱雀是 TrueType glyf（.ttf）**：对应 `Type0` + `CIDFontType2`（TrueType CIDFont），兼容性最好；很多 Rust PDF 库（如只支持 `glyf` 的实现）对 TTF 支持更完整。
- **选择建议**：若阶段 2 的 PDF 库对 CFF 支持不完整，优先用 TTF 的霞鹜文楷/朱雀覆盖对应槽位；或对 CFF 字体做 `otf2ttf` 转换（fontTools 的 cu2qu，会改变轮廓为二次曲线，需重新评估字面率）。`printpdf` 这类库历史上只嵌入 TrueType glyf，**阶段 2 前先做一次嵌入冒烟测试**。

### 8.3 子集化（subsetting）

- 推荐子集化：10 个字体全量 121 MB，整份公文通常只用几百个字形，子集后可压到几十 KB～几百 KB。
- 子集必须保留：`cmap`（或 Type0 的 `ToUnicode` CMap）、`CIDToGIDMap`、必要的 `hmtx` 宽度；CFF 字体子集要保留 FDArray/FDSelect 与 CID 结构。
- 若要求 **PDF/A** 或「可编辑/可检索文本」，必须嵌入 `ToUnicode` CMap，保证复制/检索正确；不要只嵌入 glyph 而丢 Unicode 映射。
- 子集化后仍需在 PDF 元数据/日志里记录**实际使用的字体文件 + SHA256**，便于审计（可复用 manifest 的 `sha256`）。
- 注意：若同一文档混用了商业字体与开源回退（逐字回退），PDF 会嵌入多款字体，属正常；但必须在生成日志里列出每个缺字用了哪个回退字体。

### 8.4 全角/半角、字距与网格

- 中文标点、汉字全部按全角（advance 1000/em）排版；**页码必须用半角数字 U+0030–U+0039**（标准 7.5 明确「半角宋体阿拉伯数字」），不要用全角 `０–９`（朱雀缺全角数字，万一误用会直接缺字）。
- 发文字号/成文日期中的阿拉伯数字：按 GB/T 15835 用半角数字；「〔〕」是全角六角括号。
- 每字步进用 15.7929 pt、行距用 28.9907 pt（§2）；「空一行/空二行」用 30 pt/行。
- 字体全部 1000/1000 em，不需要为不同字体调整字号来「凑版心」；差异只在字面率。

### 8.5 颜色与图形

- 正文黑：RGB `#000000`（印刷 K100）。
- 红色（机关标志、分隔线、印章、签名章）：屏幕 RGB `#FF0000`；印刷按 6.2 要求 CMYK `M80 / Y80`（近似 RGB `#FF3333`，最终以印厂色彩管理为准）。
- 红色分隔线：与版心等宽；版记分隔线粗线推荐 0.35 mm、细线 0.25 mm（7.4.1）。
- 印章/签名章是**图形资源**，见 §9，禁止用字体字形伪造。

### 8.6 页码规则（易错）

- 版心下边缘之下，数字左右各一条一字线；一字线上距版心下边缘 **7 mm**。
- 单页码居右空一字，双页码居左空一字。
- 版记页前有空白页的，空白页和版记页均不编排页码。
- 附件与正文一起装订时页码连续编排。
- 信函格式首页不显示页码（10.1）。

### 10.1 环境与工具

- 开源替代可以覆盖**全部 GB2312 常用字 + 全角标点 + 半角数字**，满足绝大多数公文正文/标题/版记的排版；
- 「小标宋」「仿宋_GB2312」的**字形观感**只能近似；
- **GB18030 生僻字是共同短板**，必须靠用户字体/系统字体兜底并显式报警。

## 11. 复现与校验（脚本用法）

```bash
# 1) 下载 + SHA256 校验 + 安装（幂等；已存在且校验通过则跳过）
bash gbt9704/scripts/fetch-fonts.sh

# 2) 只校验现有 fonts/，不联网
bash gbt9704/scripts/fetch-fonts.sh --check

# 3) 删除 .scratch/fonts-cache/ 下载缓存（字体文件保留）
bash gbt9704/scripts/fetch-fonts.sh --clean

# 4) 若 fontTools 版本不同导致 Noto 拆分产物哈希变化（内容等价）
bash gbt9704/scripts/fetch-fonts.sh --skip-derived-check
```

依赖：`bash`、`curl`、`sha256sum`、`unzip`、`dpkg-deb`（或 `ar` + `tar`）、`python3` + `fontTools`（Noto 拆 TTC 用；缺失时脚本会尝试 `pip install --target gbt9704/.scratch/pylib fonttools==4.68.0`）。

行为说明：

- 所有下载归档做**强 SHA256 校验**；Fandol/霞鹜/朱雀的解出文件与归档内容逐字节一致，也做强校验。
- Noto 从 Debian TTC 拆分，`head.modified` 已关闭（`recalcTimestamp=False`），本机重复运行字节一致；跨 fontTools 版本可能不同，故拆分产物为「弱校验」（deb 包哈希已强校验）。
- 任一来源失败自动换镜像（sustech → aliyun → ctan/deb.debian.org；朱雀 AtomGit → GitHub），仍失败则给出明确错误退出，不伪造校验值。
- 脚本在 `fonts/README.md` 自动生成来源/许可/哈希清单，与本文档 §4 一致。

## 12. 风险、限制与后续建议

**已知风险/限制**

1. **没有开源「小标宋」**：标题/机关标志只能用 Noto Serif Bold 近似，严格送审需商业字体。
2. **仿宋_GB2312 无开源等价**：FandolFang 观感接近但 GPL（不宜随项目分发）；朱雀是 OFL 但技术预览且风格化。
3. **GB18030 生僻字**：所有开源字体覆盖都不完整，必须依赖用户/系统字体；生成器需实现逐字回退 + 缺字码位报告。
4. **Fandol 的 GPL 合规**：CTAN 包内只有 COPYING（GPLv3）与 README（称 GPL + GPL font exception），**没有随附例外条款原文**；严格意义上「随软件分发」有风险（Debian 因此拒绝打包）。本项目只做本地下载。
5. **字体二进制不在版本库**：新环境需要运行脚本下载（或自备商业字体）；CI 需要网络或预置 cache。
6. **霞鹜文楷部分字形为日式写法**；**朱雀家族名带「(technical preview)」**，生成器不要硬编码家族名，按 manifest 文件路径加载。

**阶段 2 待办（字体侧）**

- [ ] PDF 库冒烟测试：CFF/OTF（Noto/Fandol）与 TTF（霞鹜/朱雀）分别嵌入 + 子集化 + 复制文本（ToUnicode）验证。
- [ ] 用 `Noto Serif Bold` 与 `FandolSong-Bold` 各生成一份 2 号标题对照 PDF，评估小标宋近似效果。
- [ ] 用 `FandolFang` / `朱雀` / `Noto Serif` 生成同一段 3 号 28 字 × 22 行对照 PDF，实测字面率溢出与可读性，确定是否启用 15.79 pt 网格步进。
- [ ] 实现「缺字检测 + 回退日志」：加载时构建 cmap 集合，缺字时按 §7 顺序回退并记录 `(码位, 回退字体)`。
- [ ] 商业字体探测与 `fsType` 检查（`fsType & 0x2` 拒绝嵌入）。
- [ ] 可选：引入思源宋体 SemiBold 静态实例改善小标宋近似（体积 +~24 MB）。
- [ ] 可选：为 PDF/A 或印刷场景补充 CMYK 红色配置与字体嵌入策略。
